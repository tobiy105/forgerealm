# Database migrations

Postgres schema for the ForgeRealm site DB on Neon.

## Files

- **`001_init.sql`** — full schema. Apply with `psql <NEON_URL> -f 001_init.sql`.
- **`_dump-seed.cjs`** — one-shot script that reads the two tables that have
  data (`admin_users`, `users`) out of the current MySQL RDS and writes a
  Postgres-compatible `INSERT` script to `_seed.local.sql`. Requires the
  MySQL creds already in `backend/.env`.
- **`_seed.local.sql`** — generated by `_dump-seed.cjs`. Gitignored because it
  contains password hashes. Apply with `psql <NEON_URL> -f _seed.local.sql`.

## Migration runbook

```
# 1. Get Neon connection string from https://console.neon.tech
export NEON_URL='postgresql://...'

# 2. Apply schema
psql "$NEON_URL" -f backend/migrations/001_init.sql

# 3. Dump the ~11 rows of live data from RDS -> local file
node backend/migrations/_dump-seed.cjs

# 4. Import the seed
psql "$NEON_URL" -f backend/migrations/_seed.local.sql

# 5. Verify row counts
psql "$NEON_URL" -c 'SELECT (SELECT COUNT(*) FROM users) AS users, (SELECT COUNT(*) FROM admin_users) AS admin;'

# 6. Once the backend PR is deployed and prod is verified green, delete
#    _seed.local.sql and _dump-seed.cjs — they've served their purpose and
#    hold PII we don't want lingering in the repo checkout.
```

Only `001_init.sql` is meant to be tracked in git long-term. The `_dump*` and
`_seed*` files are transient one-shot tooling.
